# Pokedex Specifications

This folder contains the requirements for the Pokedex application.

## Purpose

The purpose of this document is to provide a shared understanding of the requirements for the Pokedex application. It is intended for all stakeholders, including developers, testers, and product owners and ai's.

## Specification workflow

1. Read the relevant specification before coding.
2. Write or update the requirements.
3. Implement the requirements.
4. Test the implementation against the requirements.
5. Update the specification when the agreed behavior changes.

## Documents

- product.md - Product vision and scope.
- requirements.md - Shared functional requirements.
- architecture.md - Technical decisions.
- glossary.md - Common terms.
- features/ - Feature-specific requirements.

## Requirement IDs

Use IDs such as:

- FR-001 - Functional requirement.
- NFR-001 - Non-functional requirement.
- AC-001 - Acceptance criterion.

Every feature should have clear acceptance criteria.
